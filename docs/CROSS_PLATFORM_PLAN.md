# Cross-platform Nix dotfiles - build plan

Plan for a **new** repository that installs the same package set on macOS, Linux,
and Windows (via WSL2), driven by an interactive installer that prompts for the
per-user values instead of hardcoding them.

> This document is a blueprint for a fresh repo (e.g. `dotfiles`), not a change
> to the current `dotfiles-mac-nix`. The current repo is the reference source
> for the package list and the Nix-managed tooling modules.

---

## 1. Goals

1. **One shared package set** across macOS, Linux, and Windows/WSL2.
2. **Interactive installer** that prompts for and fills:
   `home.username`, `home.homeDirectory`, `dotfilesDir`, git `user.name`,
   git `email` (plus auto-detected `system`).
3. **Cross-platform, low-friction install** - one command per OS, with the
   prerequisites for each OS listed and (where possible) auto-installed.
4. Reproducible: no ad-hoc `npm i -g` / `brew install` / `cargo install`.
   Nix is the single source of truth (same rule as the current repo).

### Platform strategy (decided)

| OS | Mechanism | Nix layer |
|----|-----------|-----------|
| macOS | `nix-darwin` + home-manager module | `darwinConfigurations.<host>` |
| Linux (any distro) | standalone home-manager | `homeConfigurations.<user>` |
| Windows | WSL2 + a distro, then the **Linux path** inside WSL | `homeConfigurations.<user>` |

Windows runs the identical Linux flow inside WSL2 - Nix does not run natively on
Windows. Native Windows GUI apps are out of scope.

---

## 2. Architecture

Single flake, three consumer surfaces sharing one common module.

```
flake.nix
 ├─ darwinConfigurations.<host>      # macOS: nix-darwin + hm module
 ├─ homeConfigurations.<user>        # Linux + WSL2: standalone home-manager
 └─ (optional) formatter / checks

modules/
 ├─ common.nix        # SHARED: home.packages (CLI), git, zsh, starship, EDITOR
 ├─ darwin.nix        # macOS-only: homebrew, system.defaults, nix-darwin bits
 ├─ linux.nix         # Linux/WSL-only: linux GUI/pkg equivalents, fontconfig
 ├─ gui.nix           # cross-platform GUI apps available in nixpkgs (wezterm...)
 └─ agent-tooling/    # ported from current repo: axi, rtk, caveman, ccusage, codegraph
```

**Split rule:** anything cross-platform (CLI tools, fonts, shell, git, agent
tooling) lives in `common.nix` and is imported everywhere. Anything
platform-bound (Homebrew casks, macOS `system.defaults`, tiling WMs) lives in
the per-OS module and is imported conditionally.

### Config injection (the prompted values)

The five prompted values + detected `system` live in a single generated file
`config.nix` at repo root:

```nix
# config.nix - generated by the installer; commit this to YOUR fork.
{
  username      = "allan";
  homeDirectory = "/Users/allan";      # /home/<user> on Linux/WSL
  dotfilesDir   = "/Users/allan/dotfiles";
  gitName       = "Allan Jeo Joseph";
  gitEmail      = "you@example.com";
  system        = "aarch64-darwin";    # auto-detected: {aarch64,x86_64}-{darwin,linux}
}
```

`flake.nix` imports `./config.nix` and threads the values into the modules via
`specialArgs`/`extraSpecialArgs`. Modules stop hardcoding `allan`/`/Users/allan`
and read `cfg.username`, `cfg.homeDirectory`, etc.

**Flake purity caveat (must handle):** a Nix flake in a git repo ignores
**untracked** files, so a freshly generated `config.nix` is invisible to `nix
build` until it is staged. The installer therefore runs `git add -f config.nix`
after writing it. Model: fork the repo, run the installer once, commit
`config.nix` to your fork. (`config.nix` is listed in `.gitignore` only as a
template guard; the installer force-adds the real one. Alternatively keep it out
of git and build with `--impure` reading an absolute path - documented as the
fallback, but tracked-file is the default because it stays reproducible.)

## 3. Repository layout

```
dotfiles/
├─ flake.nix
├─ flake.lock
├─ config.nix                 # generated per-user (see §2)
├─ config.example.nix         # committed template with placeholders
├─ modules/
│  ├─ common.nix
│  ├─ darwin.nix
│  ├─ linux.nix
│  ├─ gui.nix
│  └─ agent-tooling/          # axi-packages.nix, axi.nix, rtk.nix, caveman.nix,
│                              # ccusage.nix, codegraph.nix (ported, de-hardcoded)
├─ files/                     # dotfiles symlinked by home-manager (nvim, wezterm, agent cfg)
├─ install.sh                 # POSIX entry point: macOS + Linux + inside-WSL
├─ install.ps1                # Windows: enable WSL2, install distro, hand to install.sh
├─ lib/
│  └─ prompt.sh               # shared prompt/detect helpers
├─ tests/
│  └─ install_test.sh         # PATH-masked stub test (pattern from current mac_setup_test.sh)
├─ README.md
└─ CROSS_PLATFORM_PLAN.md     # this file
```

## 4. Shared package set

Ported from the current repo's `home.packages`, kept in `common.nix` so all
three platforms get the identical CLI environment.

**Common CLI (all platforms):**
`git`, `curl`, `wget`, `jq`, `fd`, `fzf`, `fastfetch`, `neovim`, `ripgrep`,
`lazygit`, `tree`, `bun`, `rustup`, `zip`, `unzip`
- `killall` is Linux-only in nixpkgs; on macOS it's a system builtin - guard it
  behind `lib.optionals stdenv.isLinux`.

**Fonts (all platforms, via `fonts.fontconfig` on Linux / darwin fonts on mac):**
`nerd-fonts.hack`, `roboto`, `noto-fonts`, `noto-fonts-cjk-sans`,
`noto-fonts-color-emoji`, `font-awesome`

**Shell / programs (home-manager modules, all platforms):**
`git` (+lfs), `starship`, `zsh` (oh-my-zsh, autosuggestion, syntax-highlighting)

**Agent tooling (all platforms - port the current Nix modules):**
`gh-axi`, `chrome-devtools-axi`, `lavish-axi`, `rtk`, `ccusage`, `codegraph`,
caveman (`caveman-activate`, `caveman-mode-tracker`, `python3`).
- These modules currently pin `aarch64-darwin` prebuilt binaries (rtk, ccusage,
  codegraph fetch `*-darwin-arm64` tarballs). For Linux/WSL they need the
  `*-linux-x64` / `*-linux-arm64` release artifacts selected by `system`. Build
  a small `pkgs.fetchurl` selector keyed on `system` per tool. The three AXI
  CLIs + chrome-devtools-mcp build from source via pnpm and are already
  platform-portable.

### Platform GUI / app equivalents

The current macOS Homebrew casks/brews do not all exist off macOS. Mapping:

| Current (mac) | Linux / WSL equivalent | Notes |
|---------------|------------------------|-------|
| cask `wezterm` | nixpkgs `wezterm` | cross-platform; GUI in WSL needs WSLg |
| cask `amethyst` | (none) | macOS-only tiling WM; drop on Linux, or `i3`/`hyprland` opt-in |
| cask `opensuperwhisper` | (none) | macOS-only; drop |
| cask `zulu@17` | nixpkgs `zulu17` / `temurin-bin-17` | JDK; portable |
| brew `postgresql@18`, `postgis` | nixpkgs `postgresql_18` + `postgisPackage` | portable |
| brew `ffmpeg`, `direnv`, `gh`, `watchman`, `pyenv`, `act`, `opentofu`, `ktlint`, `cocoapods`, `bear`, `autoconf`, `cf-terraforming`, `git-filter-repo`, `mongodb-database-tools`, `pinentry-mac` | mostly in nixpkgs (`pinentry` not `pinentry-mac`; `cocoapods` mac-only) | move portable ones into `common.nix`; keep mac-only ones in `darwin.nix` |
| brew `herdr` (tap) | evaluate per-tool | may be mac-only |

**Homebrew stays macOS-only** (in `darwin.nix`, keeping the `zap` cleanup
policy). On Linux/WSL the equivalents come from nixpkgs. GUI apps that only make
sense on a desktop are guarded so a headless WSL install skips them.

### Neovim plugins

Not Nix-managed (fetched by neovim's built-in `vim.pack`, pinned in
`nvim-pack-lock.json`). The `files/.config/nvim/` config is symlinked on every
platform, so plugins install identically everywhere. Plugins:
`plenary.nvim`, `mini.icons`, `snacks.nvim`, `oil.nvim`, `neogit`,
`diffview.nvim`, `gitsigns.nvim`, `which-key.nvim`.

## 5. Installer design

### 5.1 Prompt + detect (`lib/prompt.sh`, used by `install.sh`)

1. Detect `system` from `uname -sm` -> one of
   `{aarch64,x86_64}-{darwin,linux}`.
2. Prompt (with sensible auto-detected defaults; press-enter accepts):
   - `username`      default: `$(id -un)`
   - `homeDirectory` default: `$HOME`
   - `dotfilesDir`   default: `$HOME/dotfiles` (repo clone location)
   - `gitName`       default: `git config --global user.name` if set
   - `gitEmail`      default: `git config --global user.email` if set
3. Write `config.nix`, then `git add -f config.nix`.
4. Idempotent: re-running re-prompts with existing `config.nix` values as
   defaults.

### 5.2 macOS / Linux flow (`install.sh`)

```
ensure prerequisites (see §6)  ->  install Nix (Determinate) if absent
  ->  source nix profile into current shell (single-pass, no re-login)
  ->  clone/update repo at $dotfilesDir
  ->  run prompt + write config.nix
  ->  activate:
        macOS:  sudo nix run nix-darwin#darwin-rebuild -- switch --flake .#<host>
        Linux:  nix run home-manager -- switch --flake .#<user>
```

Reuse the current repo's proven bootstrap discipline:
- Single-pass on a fresh machine (source the daemon profile so `nix` is usable
  immediately; use an absolute `nix` path under `sudo`).
- Overridable env vars for every real side-effecting path so the test harness
  can sandbox them (`NIX_DAEMON_PROFILE`, `DARWIN_REBUILD_BIN`, `REPO_URL`,
  `DOTFILES_DIR`, `DOTFILES_BRANCH`, ...).
- Already-installed fast path stays untouched.

### 5.3 Windows flow (`install.ps1`)

```
(admin) enable WSL2 feature + VirtualMachinePlatform  ->  wsl --install -d Ubuntu
  ->  set WSL2 as default  ->  inside the distro:
        curl -fsSL <raw install.sh> | bash    # identical Linux path
```

`install.ps1` only bootstraps WSL2 and hands off; **all** package logic lives in
`install.sh` so Windows and Linux never diverge. WSLg gives GUI apps (wezterm) a
display; headless installs skip GUI modules.

### 5.4 One-liner entry points

- macOS / Linux: `curl -fsSL https://raw.githubusercontent.com/<you>/dotfiles/main/install.sh | bash`
- Windows (PowerShell, admin): `irm https://raw.githubusercontent.com/<you>/dotfiles/main/install.ps1 | iex`

## 6. Prerequisites per OS

### macOS
- **Xcode Command Line Tools** (`xcode-select --install`) - for `git` + build
  toolchain. Installer triggers and waits, same as current `bootstrap.sh`.
- **Nix** - Determinate installer (installer runs it if absent).
- Admin rights (nix-darwin activation uses `sudo`).
- Homebrew is auto-managed by `nix-homebrew` (no separate install).

### Linux (any distro)
- **A POSIX shell + `curl`/`git`** (usually preinstalled; installer checks and
  prints the distro package command if missing).
- **Nix** - Determinate/official installer (installer runs it if absent).
  Multi-user (daemon) install needs `sudo`; single-user works rootless.
- **systemd** recommended for the Nix daemon; on non-systemd distros use the
  daemonless/rootless install path.
- `xdg-utils` + a font cache (`fontconfig`) for the font packages.

### Windows
- **Windows 10 21H2+ / Windows 11** (WSL2 support).
- **Admin PowerShell** once, to enable WSL2 (`install.ps1`).
- **WSL2 + a distro** (Ubuntu) - `install.ps1` installs it.
- **WSLg** (bundled with recent WSL) for any GUI app; optional for headless.
- Virtualization enabled in BIOS/UEFI (required by WSL2).
- After WSL is up, prerequisites collapse to the **Linux** list above, run
  inside the distro.

## 7. Migration steps (from current repo to new repo)

1. **Scaffold** the new repo with the layout in §3; copy `files/` verbatim.
2. **Extract `common.nix`** from the current `nix/user.nix`: move
   `home.packages`, `programs.git/zsh/starship`, session vars. Replace every
   hardcoded `allan` / `/Users/allan` / dotfiles path with `cfg.*` values.
3. **Extract `darwin.nix`** from `nix/host.nix`: Homebrew (keep `zap`),
   `system.defaults`, `nix-homebrew`, primary user - all guarded to darwin.
4. **Author `linux.nix`**: fontconfig, Linux-only package guards, GUI opt-ins.
5. **Port agent-tooling modules** (`axi*`, `rtk`, `caveman`, `ccusage`,
   `codegraph`): add a `system`-keyed source selector so Linux pulls the
   `*-linux-*` release artifacts; keep the bare-name-on-PATH + declarative-hook
   conventions. Verify each upstream ships Linux binaries; build from source
   where it doesn't.
6. **Write `flake.nix`** exposing `darwinConfigurations` + `homeConfigurations`,
   importing `config.nix`.
7. **Write `install.sh` / `install.ps1` / `lib/prompt.sh`**.
8. **Port the test harness** (`tests/install_test.sh`) from the current
   `tests/mac_setup_test.sh`: PATH-masked stubs, sandboxed `HOME`, never touch
   real Nix/Homebrew/network/sudo. Extend it with a Linux `home-manager switch`
   stub path and a WSL hand-off stub.
9. **README** with the three one-liners + per-OS prerequisites.

## 8. Risks / open questions

- **Agent-tool Linux binaries - VERIFIED, all covered.** Checked upstream:
  - `rtk` v0.43.0: ships `aarch64-unknown-linux-gnu` + `x86_64-unknown-linux-musl`
    (also `.deb`/`.rpm`). Selector caveat: x86_64-linux is **musl-only**,
    aarch64-linux is **gnu-only** - map accordingly (musl static runs anywhere).
  - `codegraph` v1.3.0: ships `codegraph-linux-arm64` + `codegraph-linux-x64`.
  - `ccusage` 20.0.14: npm `@ccusage/ccusage-linux-{x64,arm64}` both present.
  - AXI CLIs + `chrome-devtools-mcp` + caveman: build from source / pure Node -
    portable, no artifact needed.
  Remaining work is just the `system`-keyed `fetchurl` selector per tool, not a
  question of availability.
- **Flake purity vs generated config.** Decided: track `config.nix` in the
  user's fork (installer force-adds it). Revisit if a no-commit flow is required
  (then `--impure` + absolute path).
- **GUI in WSL.** wezterm/GUI apps need WSLg; document the headless fallback
  (terminal-only) so a server install still succeeds.
- **macOS-only apps** (`amethyst`, `opensuperwhisper`, `cocoapods`,
  `pinentry-mac`) have no Linux equivalent - they simply don't appear in the
  Linux/WSL package set; optional Linux substitutes (`i3`/`hyprland`,
  `pinentry-gtk`) can be added later.
- **Determinate installer on exotic distros** (non-systemd, musl): fall back to
  the official rootless installer; test on at least Ubuntu + Fedora + Arch.

---

## 9. Definition of done

- `install.sh` on a fresh macOS **and** a fresh Ubuntu produces an identical
  CLI/agent environment from one command, prompting for the five values.
- `install.ps1` on fresh Windows brings up WSL2 and reaches the same end state.
- `config.nix` is the only file that differs between users.
- `tests/install_test.sh` passes for macOS, Linux, and WSL-handoff paths with
  no real system mutation.
